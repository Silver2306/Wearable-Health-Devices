Machine Learning Semester Project Proposal

Comparative Performance Analysis of Machine Learning Algorithms for Stress-Level Classification Using Wearable Health Data

This project investigates how effectively machine learning models can classify a person's stress level using daily physiological, activity, sleep, lifestyle, and demographic indicators represented in a wearable-health dataset.

Problem type Multi-class classification
Target Stress level
Models compared 4 algorithms
Data source Kaggle

1. Project Overview

Short Description

Wearable devices continuously record indicators such as heart rate, heart-rate variability, activity, sleep patterns, and other wellness-related measurements. The proposed study will use these indicators to classify daily stress into meaningful categories and compare the predictive performance of four machine learning algorithms.

The study is comparative rather than model-specific. Every model will be trained and evaluated using the same cleaned dataset, features, data split, and metrics so that the final comparison remains fair and academically valid.

Core Objective

To determine which selected machine learning algorithm provides the most suitable balance of classification performance, computational efficiency, interpretability, and practical value for stress-level prediction using wearable health data.

2. Selected Dataset

The proposed dataset is “Health + Wearables + Stress/Sleep Tracking (Synthetic)”, published on Kaggle. It represents approximately six months of daily health tracking for 300 individuals and was generated using a physiologically realistic synthetic model.

≈54,000 Daily records based on 300 individuals tracked for about 180 days
300 Distinct synthetic users
≈6 months Longitudinal observation period
Mixed Numerical, categorical, physiological, behavioural, and sleep features

Why this dataset is suitable

  • It directly combines wearable-health indicators with a stress score.
  • Its longitudinal structure represents repeated daily observations rather than isolated records.
  • It contains enough records to train, validate, and compare multiple machine learning models.
  • It supports data cleaning, categorical encoding, scaling, feature analysis, and classification.
  • Its synthetic nature avoids direct exposure of real individuals' private medical data.
Important limitation: Since the data is synthetic, the results will demonstrate model behaviour on simulated wearable-health patterns. They should not be presented as a clinically validated diagnostic system or as proof that the model will generalise to real patients.

Dataset source: Kaggle — Health + Wearables + Stress/Sleep Tracking (Synthetic)

3. Dataset Feature Groups

The dataset combines several types of information that may be associated with stress. This makes it suitable for studying how linear, margin-based, bagging, and boosting models respond to mixed health data.

Physiological

Sleep

5. Expected Objective and Output

The initial project design treats stress prediction as a multi-class classification task. The numerical stress score will be converted into interpretable classes after examining its distribution.

1

Input

Selected wearable, sleep, activity, lifestyle, and demographic features after preprocessing.

2

Model Output

A predicted stress category, provisionally defined as Low, Moderate, or High.

3

Comparative Result

A ranked and justified comparison based on predictive metrics, efficiency, and interpretability.

Provisional class definition

If the stress score ranges from 0 to 100, an initial rule may classify 0–33 as Low, 34–66 as Moderate, and 67–100 as High. However, the final thresholds will be selected only after visualising the score distribution and checking whether the classes remain reasonably balanced.

Evaluation measures

  • Accuracy
  • Macro and weighted precision
  • Macro and weighted recall
  • Macro and weighted F1-score
  • Confusion matrix
  • One-vs-rest ROC-AUC, where suitable
  • Training time
  • Prediction time

6. Selected Algorithms and Their Justification

The four models were selected because they represent different machine learning approaches. The aim is not to compare four variations of the same technique, but to study how fundamentally different learning strategies perform on the same wearable-health classification problem.

Linear Model · Baseline

1. Logistic Regression

Why it is needed: It provides a simple and interpretable baseline against which more complex models can be judged.

Why it suits the study: It can show whether the selected health indicators have a sufficiently clear linear relationship with the stress classes.

What the team will learn: Probability-based classification, sigmoid or softmax output, decision boundaries, coefficients, regularisation, scaling, and the importance of establishing a baseline.

Expected limitation: It may underperform if stress is produced by complex nonlinear interactions among sleep, activity, and physiological features.

Margin-Based Model

2. Support Vector Machine

Why it is needed: SVM introduces a model that separates classes by maximising the margin between them rather than directly modelling probabilities.

Why it suits the study: Kernel functions allow it to model nonlinear boundaries that may exist among mixed wearable-health indicators.

What the team will learn: Hyperplanes, support vectors, margins, kernels, feature scaling, and the effect of parameters such as C and gamma.

Expected limitation: Training can become computationally expensive on larger datasets, and the model is less directly interpretable than Logistic Regression.

Tree Ensemble · Bagging

3. Random Forest

Why it is needed: It represents the bagging approach, where many decision trees are trained on varied samples and combined through voting.

Why it suits the study: It naturally captures nonlinear relationships and feature interactions, handles mixed feature patterns, and is generally robust to noise.

What the team will learn: Decision trees, bootstrap sampling, random feature selection, majority voting, overfitting control, and feature importance.

Expected limitation: It can be less transparent than a single linear model and may require control of tree depth and ensemble size.

Tree Ensemble · Boosting

4. Gradient Boosting Classifier

Why it is needed: It adds the boosting approach, where weak learners are built sequentially and each new learner focuses on correcting earlier errors.

Why it suits the study: It can capture subtle nonlinear patterns and interactions in structured tabular data while remaining manageable within the scikit-learn ecosystem.

What the team will learn: Sequential ensemble learning, weak learners, residual error correction, learning rate, number of estimators, and the distinction between bagging and boosting.

Expected limitation: It is more sensitive to hyperparameter choices and may take longer to tune than the baseline models.

Why these four form a meaningful comparison

Together, the models create a progression from a simple linear baseline to increasingly flexible nonlinear methods. Logistic Regression tests linear separability, SVM tests maximum-margin and kernel-based learning, Random Forest represents parallel bagging, and Gradient Boosting represents sequential error-correcting ensembles. This diversity gives the comparative study greater academic value than selecting multiple algorithms from the same family.

7. Learning Outcomes for the Team

The project will help the team understand not only how to run algorithms, but also how to design and defend a fair machine learning experiment.

Data Understanding Learn how wearable, sleep, physiological, and lifestyle features may relate to stress.
Preprocessing Practise missing-value treatment, encoding, scaling, outlier review, and leakage prevention.
Model Behaviour Compare linear, margin-based, bagging, and boosting approaches on identical data.
Evaluation Understand why accuracy alone is insufficient and how precision, recall, F1-score, and confusion matrices differ.
Hyperparameter Tuning Study how model settings affect underfitting, overfitting, training time, and generalisation.
Interpretability Examine coefficients, feature importance, and the trade-off between explainability and predictive power.
Experimental Fairness Apply the same train-test logic, preprocessing, and metrics across all models.
Critical Discussion Learn to explain why a model performed well or poorly instead of reporting scores without analysis.

9. Expected Final Outcome

The project will produce a comparative evaluation identifying which of the four models is most suitable for stress-level classification on the chosen dataset. The conclusion will not be based only on the highest accuracy. It will consider F1-score, class-wise errors, computational requirements, interpretability, sensitivity to preprocessing, and suitability for a wearable-health application.

The final outcome will therefore answer both a predictive question—which model performs best?— and an analytical question—why does that model perform better for this type of data?
